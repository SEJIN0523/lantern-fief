너는 GitHub 저장소 SEJIN0523/lantern-fief 에 직접 연결해서 코드를 수정하는 작업자다.
이 저장소는 안드로이드 휴대폰 세로 화면용 웹앱 픽셀 JRPG "등불 영지 — 이계의 영주"이며,
main 브랜치에 합쳐지면 GitHub Pages(https://sejin0523.github.io/lantern-fief/)로 바로 배포된다.
모든 설명, 커밋 메시지, PR 설명, 게임 안 문구는 한국어로 쓴다.

# 이번 작업 목표
게임 안 아이콘(아이템 아이콘 + 화면 곳곳의 UI 아이콘)의 품질이 낮다.
지금은 AI가 그린 그림 시트를 128px로 잘라 작게 줄여 쓰고 있어서, 휴대폰에서 뭉개지고 모양이 제각각이다.
이것을 "코드로 그린 픽셀 아이콘(SVG)" 한 벌로 바꿔서, 작게 보여도 또렷하고 모양과 굵기가 통일되게 만든다.

핵심 원칙 두 가지:
1. 아이템은 하나하나 구별할 필요가 없다. "어떤 종류인지(무기/방어구/장신구 등)"만 아이콘으로 보여 준다.
2. 아이템의 좋고 나쁨은 "등급"으로 나타내고, 등급은 오직 색으로만 구별한다(모양은 같고 색만 다름).

# 1. 저장소 구조 (먼저 반드시 읽을 것)
- index.html : 스크립트를 이 순서로 불러온다. 기존 순서를 바꾸지 말 것.
  art → data → units → battle → game → story → battleview → chapters → ui → romance → main
- js/art.js : ART 그림 키 → 파일 경로 표. tools/slice_art.py 가 자동으로 만든다. 절대 손으로 고치지 말 것.
- js/ui.js
  - 16행 근처 `const ICON = { gold: ["ui_icons_a_1", "💰"], ... }` : UI 아이콘 이름 → [그림 키, 대체 이모지].
  - 그 아래 `const UI_GLYPHS` : 일부 아이콘의 선 그림 SVG 경로(그림이 없을 때 대체용).
  - `function ic(name, cls)` : 모든 UI 아이콘을 그리는 함수. 그림 → 선 그림 → 이모지 순서로 고른다.
  - 304행 근처 `const ITEM_ART`, `function itemIc(id, slot)` : 상점·장비창의 아이템 아이콘.
  - 상점 목록(renderShop 근처의 .shop-it), 장비 탭(.eq 버튼), 무기 칸(.wpn-ic)에서 아이템 아이콘을 쓴다.
- js/units.js 232행 근처 `const ITEMS` : 장비 아이템(slot: "armor" 또는 "acc", 능력치, price, otherworld).
  js/chapters.js 에도 `ITEMS.phone`, `ITEMS.notebook` 이 추가로 정의되어 있다.
- js/romance.js : `GIFTS`(선물), `GIFT_ART`(선물 그림 키), 선물 상점 화면(renderGiftShop).
- js/data.js : `WEAPON_ICON`(무기 종류 → 이모지). 무기 종류: sword, axe, spear, dagger, bow, crossbow, staff, mace, fist, tool, book.
- 무기는 동료마다 하나씩 붙어 있는 고유 무기다(u.weapon.plus = 강화 수치, 대장간에서 올림. +20/+40/+60에서 각성).
- style.css : 전체 스타일. 같은 선택자가 파일 뒤쪽에서 여러 번 덮어쓰인다(.ic 크기 규칙 등).
  새 규칙은 파일 맨 끝에 "/* 아이콘 v2 */" 같은 주석 제목을 달고 모아서 붙일 것.
- sw.js : 오프라인 캐시. 상단 VERSION 문자열("fief-vNN")의 숫자를 1 올릴 것.
  새 js 파일을 만들면 FILES 목록에도 반드시 넣을 것(빠지면 오프라인에서 깨진다).
- art/ 폴더 : 그림 원본. 절대 수정·삭제·이동하지 말 것. 이번 작업은 그림 파일을 새로 만들지 않는다.

# 2. 만들 것
## 2-1. 새 파일 js/icons.js
- index.html 에서 art.js 바로 다음에 불러오고, sw.js FILES 에도 추가.
- 여기에 모든 아이콘을 SVG 문자열로 정의한다. 외부 라이브러리·폰트·이미지 파일 사용 금지.

## 2-2. 그림 규칙 (모든 아이콘 공통)
- 16×16 칸 픽셀 아트로 그린다: viewBox="0 0 16 16", shape-rendering="crispEdges",
  1칸짜리 <rect> 또는 칸에 맞춘 <path> 만 사용(곡선·흐림·그라디언트 금지).
- 1칸 두께의 어두운 외곽선(#10161c 근처)을 모든 아이콘에 두른다. 외곽선이 있어야 어두운 바탕에서도 보인다.
- 색은 아이콘마다 "밝은 면 / 기본 / 그림자" 3단계 + 외곽선 + 반짝임 1칸 정도로 제한한다.
- 빛은 항상 왼쪽 위에서 온다고 보고 그림자는 오른쪽 아래에 둔다.
- 화면에서는 16, 20, 24, 32, 48px 로 보이게 될 것이므로, 16px에서도 무엇인지 알아볼 수 있는 단순한 실루엣으로.
- 현재 게임 톤(어두운 청록 바탕 + 금색 강조, 따뜻한 중세 판타지)에 맞출 것.

## 2-3. 아이템 아이콘: "종류" 아이콘 + "등급" 색
종류(모양)는 아래만 만든다. 개별 아이템별 그림은 만들지 않는다.
- 무기: WEAPON_ICON 의 11종(sword, axe, spear, dagger, bow, crossbow, staff, mace, fist, tool, book) 각각 1개
  (무기 종류는 직업이 쓰는 무기를 알려 주는 정보라 종류별로는 다르게 둔다)
- 방어구 1개 (가슴 갑옷 모양)
- 장신구 1개 (반지 또는 목걸이 모양)
- 선물 1개 (리본 묶은 작은 상자) — 선물 상점과 선물 주기 화면에서 사용
- 이계 물건 1개 (otherworld: true 인 아이템용. 반짝이는 낯선 물건 느낌의 모양, 예: 금 간 사각 기기)
- 빈 칸 1개 (장비하지 않은 칸: 점선 테두리 슬롯 모양, 회색)

등급(색)은 6단계. 모양은 그대로 두고 "금속/본체 색"만 등급 색 3단계(밝음/기본/그림자)로 바꾼다.
나무 손잡이·가죽끈처럼 재료 고유색인 부분은 등급과 상관없이 그대로 둔다.
  0 일반  : 회색 철빛      (예: #d7dde0 / #9aa6ad / #5d6870)
  1 고급  : 초록           (예: #b8f0a0 / #5fbf4f / #2f6e2c)
  2 희귀  : 파랑           (예: #a8d8ff / #4a90e0 / #24508a)
  3 영웅  : 보라           (예: #e0b8ff / #9a5ae0 / #55308a)
  4 전설  : 금빛 주황      (예: #ffe39a / #f0a030 / #9a5a14)
  5 이계  : 청록에서 분홍으로 빛나는 색 (예: #a8fff0 / #40d0c0 / #c050a0 를 섞어 씀)
구현 방법: SVG 안에서 등급 색이 들어갈 부분을 fill="var(--g1)" / "var(--g2)" / "var(--g3)" 로 쓰고,
감싸는 요소에 class="grade-0" ~ "grade-5" 를 달아 style.css 에서 --g1~--g3 값을 정해 준다.
그렇게 하면 등급별로 SVG를 따로 만들 필요가 없다.

등급 정하는 규칙(새 필드 grade 를 데이터에 넣는다. 능력치·가격은 바꾸지 말 것):
- ITEMS(장비): 가격 기준으로 정한다. price ≤ 50 → 0, ≤ 100 → 1, ≤ 200 → 2, 그 이상 → 3.
  otherworld: true 인 아이템(pen, phone, notebook) → 5.
  units.js 의 ITEMS 각 항목과 chapters.js 의 ITEMS.phone / ITEMS.notebook 에 grade 를 직접 적을 것.
  (나중에 아이템이 늘어도 grade 가 없으면 위 가격 규칙으로 계산하는 함수 itemGrade(it) 도 함께 만들 것)
- 무기(동료 고유 무기): 강화 수치로 정한다. +0~9 → 0, +10~19 → 1, +20~39 → 2, +40~59 → 3, +60 이상 → 4.
  함수 weaponGrade(u) 로 만들 것.
- 선물(GIFTS): 반지(ring)는 4, 나머지는 가격 기준(≤ 30 → 0, ≤ 80 → 1, 그 이상 → 2).

## 2-4. 등급 표시 방식
- 아이콘 자체 색 + 아이콘 뒤 작은 칸(배경)의 테두리 색을 등급 기본색으로.
- 아이템 이름 글자색도 등급 색(밝은 쪽)으로. 단, 일반(0)은 기존 글자색 그대로.
- 전설(4), 이계(5)만 아이콘 칸에 아주 약한 빛(box-shadow 정도)을 준다. 깜빡이는 애니메이션은 금지.
- 장비 탭과 상점에서 등급 이름(일반/고급/희귀/영웅/전설/이계)을 작은 글씨로 함께 보여 준다.

## 2-5. UI 아이콘 다시 그리기
js/ui.js 의 ICON 표에 있는 이름 전부를 같은 규칙(16×16 픽셀, 외곽선, 3단 명암)으로 다시 그린다.
대상: gold, food, wood, stone, pop, morale, village, party, form, expe, moon, atk, def, mag, spd, hp, pot,
lock, quest, bell, build, lantern, boss, skull, injury, tired, lvup, forge, chest, book, armor, ring, weapon,
status, rest, shop, recruit, log, worker
- 각 아이콘의 뜻은 지금 대체 이모지(ICON 표의 두 번째 값)를 기준으로 삼는다.
- 자원 아이콘(gold/food/wood/stone)은 상단 자원 칸에서 크게(약 32px) 보이니 가장 공들여 그릴 것.
- 아래 탭 아이콘(village/party/moon/form/expe)은 선택/비선택 상태가 있으니 단색으로 바꿔도 알아볼 수 있는 실루엣으로.
- ui.js 의 ICON 표 안에 있는 다른 이름이 더 있으면 그것도 빠짐없이 그릴 것.

## 2-6. 함수 연결
- ic(name, cls): js/icons.js 의 SVG 가 있으면 그것을 먼저 쓰고, 없을 때만 지금 방식(그림 → 선 그림 → 이모지)으로.
  class="ic ..." 는 그대로 유지해서 기존 크기 규칙이 계속 먹게 할 것.
- itemIc(id, slot) 를 새 방식으로: ITEMS[id] 의 종류(slot, otherworld)와 등급으로 아이콘을 만든다.
  ITEM_ART 는 지우지 말고 더 이상 쓰지 않게만 둘 것(나중에 되돌릴 수 있게).
- 무기 칸(.wpn-ic)은 그 동료 직업의 무기 종류 아이콘 + weaponGrade(u) 색.
- 선물 상점·선물 주기 화면(romance.js)은 GIFT_ART 대신 선물 아이콘 + 선물 등급 색. GIFT_ART 도 지우지 말 것.
- 같은 함수를 쓰는 곳이 더 있으면 grep 으로 찾아 모두 새 방식으로 보이는지 확인할 것.

# 3. 코드 규칙
- 빌드 도구·프레임워크·npm 패키지 추가 금지. 순수 JavaScript, 전역 함수, "use strict".
- 주변 코드와 같은 문체: 짧은 한국어 주석, 템플릿 문자열로 HTML 생성.
- 저장 데이터(localStorage 의 G)를 깨뜨리지 말 것. grade 는 ITEMS 정의에만 넣고 저장 데이터에는 넣지 않는다.
- 게임 수치(능력치, 가격, 확률, 경험치) 변경 금지. 대사·스토리 문구 변경 금지.
- 전투 화면, 캐릭터·몬스터·건물 그림, 대화창은 이번 작업 범위가 아니다. 건드리지 말 것.
- 파일 전체를 다시 쓰지 말고 필요한 부분만 고칠 것.

# 4. 화면 기준과 확인
- 기준 화면: 가로 412px 휴대폰 세로. 360px 폭에서도 가로 스크롤이 생기면 안 된다.
- 저장소 루트에서 정적 서버로 확인(예: python -m http.server 8765).
- 확인 순서: 새 게임 → 프롤로그 넘기기 → 상단 자원 칸 → 아래 탭 5개 → 마을의 상점(장비 상점, 선물 상점)
  → 동료 상세창의 장비 탭(빈 칸, 방어구, 장신구, 무기) → 원정 1회 전투 → 하루 마치기.
  브라우저 콘솔 오류가 없어야 한다.
- 등급 6단계가 한눈에 보이는 확인용 화면 캡처를 만들 것: 개발자 도구 콘솔에서 임시로
  모든 종류 × 모든 등급 아이콘을 한 화면에 그려 캡처(이 임시 코드는 커밋하지 말 것).
- 수정 전/후 캡처(상단 자원 칸, 아래 탭, 상점, 장비 탭)를 PR 에 첨부.
